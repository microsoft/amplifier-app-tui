# Sustained work clarity — development verification

Direction: presentation.v1:4/7, interaction.v1:1, continuity.v1:1 and ecosystem.v1:4/6.
The steward approved implementation after a long delegated review exposed status,
noise and inspection defects. No kernel changes, personal settings writes, private
session rewriting or publication are included.

## Changed behavior

- Exact parent summaries retain distinct agents, current observed work, call/cost
  totals, elapsed observation, completed tool count and failed/unknown outcomes.
  Nested totals include this execution's observed descendants, not older work from
  a resumed child, without changing the session ledger. Missing historical counters
  stay unavailable rather than implying zero calls or no warnings.
  Native child usage is collapsed, not discarded; root calls and final totals remain.
- Activity reads sibling pages from the public event journal, off the input loop.
  Early usage/tool records remain accessible after eviction from the hot index.
  Source snippets remain bounded; unavailable data is not reconstructed.
- A bounded invocation-status observation survives post-hook result truncation.
  Only status is retained before hooks; content remains post-policy. Recognizable
  processed errors take precedence, and genuinely unobserved outcomes stay unknown.
- Inspection selects visible expandables; pasted text restores composer ownership.
  Hidden records no longer consume blank rows. New work preserves an existing
  inspection anchor; Escape returns to native history. Tiny views disclose overflow.
- Child modes no longer require root-local controls. Invalid recovery overrides
  refuse before writes. Switching drains old lookups and refuses obsolete replies.

## Limits and remaining judgment

- Normal terminal selection remains native. Expanding committed history still uses
  explicit Interact/Activity; this does not solve the broader copy/interaction UX tradeoff.
- At very small heights not every concurrent agent fits. Overflow is labelled;
  inspection scrolls visual lines and preserves identities, rather than hiding work silently.
- Activity pages contain at most 100 siblings / 1 MiB with 16 KiB detail excerpts;
  scans cap at 64 MiB, 10,000 identities or two seconds and disclose incomplete results.
  The private journal remains authoritative; Markdown export includes model-call usage.
- Status fallback requires the observed invocation seam. It does not retroactively
  relabel unknown historical results or prove a successful command achieved its task.
- No silent tool/provider/cost caps, retry policy or execution authority were added.
  Uncooperative module cancellation and physical-terminal/platform breadth remain
  separate limitations; controlled terminal tests are not certification of every setup.

Raw transcripts, screenshots, local receipts and live-run state remain private and
are not fixtures or distributable artifacts.
